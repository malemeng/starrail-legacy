## 2. 数值手感（实测）

- **星际成本**：锚地↔黎明-02 单程 17 天 / 7.02 燃料；信标级 70 燃料可往返 5 次左右。行星内 4000 距离 ≈ 32 天，590 距离 ≈ 5 天，巡航档位只改现实等待时长。
- **采掘**：每次 12 单位（货舱 36），矿带储量会实打实下降（162→150），所以矿不是无限 ATM。
- **首航委托定价**：8 矿石付 ¢210（26/单位），而炉心公开市场只给 10/单位。剧情委托 ≈ 2.6 倍市场价，强度合适——但一次性的。
- **套利衰减很快**：航电元件 78→96 的 34 点价差，第一趟赚 909；第二趟因为两头库存都动了，买价升到 85、卖价塌到 86 再塌到 70，第三批直接 0 收购。**两三趟就必须换线**，这个设计是有效的反挂机机制，但也意味着"航线记忆"没意义，每次都要重新 `trade_opportunities` 扫。
- **股权**：赫弧工业净资产 ¢328,790 / 3034 股 = 账面 108/股，董事长却坚持 195/股（+80% 溢价），30 天后市价跌到 129。也就是说二级市场买入是**负期望**：分红 25% × 4399 = 1100 摊到 3034 股 ≈ 0.36/股/30 日，年化不到 3%，还买在 195。反而是 `sell` 栏里卢卡斯挂的 115~131、罗启山挂的 126~143 才是合理价位——**佣金/滑点机制对散户极不友好，但对"先看挂单再成交"的玩家友好**。
- **战斗**：同型舰互殴，托管开火 300 tick 把对手打到 14.65 hp 而自己零伤，说明 AI 的护盾/走位处理是及格的；但**收尾能力差**。

## 3. 明确的 bug / 摩擦点（按严重度）

1. **`market_quote` 与实际成交严重不一致**（可复现）。同一停靠状态：
   - `market_quote {ware:12, amount:-8}` 返回 `units:8, total:836`，观战面板也打印"整批 ¢836"；
   - 立刻 `trade {ware:12, amount:-8}` 只成交 **2 单位 / ¢140**；
   - 再查同一笔报价变成 `units:0, total:0`。
   玩家按报价决策会被骗。建议：报价与撮合用同一条价格带计算，或让报价返回"预计成交 / 保底成交"两档。
2. **`order` 集火在无僚舰时静默失败**：`{"order":2,"target":8}` 返回 `error:"order_rejected"`，`detail` 为空串，无从判断是"没有护航舰"还是"目标无效"。对比 `cannot_dock` 有 `detail:"交火中不能停靠。"`，错误文案不统一。
3. **`speed_restricted_no_waypoint` 的 `detail` 也是空的**：真实原因（"未设置航点时不可在太空使用高于 1 档的倍速"）只存在于 `game.notice_text`，桥接层 `failure()` 没带上。Agent 只能靠猜。
4. **交火锁定幽灵残留**：敌舰已脱离传感器（`targets` 里只剩中立船）后 `ship.locked` 仍为 true，导致 `dock` 报"交火中不能停靠"、倍速被限 1 档；需要再空跑 600 tick 才解除。期间 `state.notice` 长期停在"交火中不能停靠"，观战面板把它当"结果"显示了几十个游戏日。
5. **观战面板的"结果"列信息量太低**：桥接返回 `result:{}` 的成功动作（交付首航、买入 34 单位、靠港）在面板上一律显示"已收到回执"，玩家看不出发生了什么。建议面板直接用 `notice` + `result` 的关键字段合成一句人话。
6. **公司分红没有被动到账**：`dividends.percent=25`、`available=4399`，`next_eligible_day` 从 330 滚到 360，`payable` 始终 0，5 股一分钱没收到。少数股东在机制上完全没有现金流，只能靠股价——而股价 30 天内从 146 跌到 129。这里要么补上自动派息，要么在 UI 明确写"公司分红须董事长发起"（`pay_company_dividend`）。
7. **托管 AI 收尾/追击不足**：敌舰 14.65 hp 且已开盾时，托管选择保持 400+ 距离绕飞，600 tick 内不再命中；手动关掉托管、`move` 指向敌舰才重新接战，而这时对方已经脱离。建议托管增加"处决"状态：目标 hp < 25% 时缩短保持距离、优先补刀。
8. **产地无收购需求**：炉心既产航电元件又在卖，却在 `market_quote` 里先给 8 单位 ¢836、随后 0 成交量，玩家把货背回产地才发现卖不掉。卖单簿最好直接显示"本站当前最大收购量"。

## 4. 做得好的地方

- **`trade_opportunities` 是这一局最有用的一个接口**：直接给 `buy_price / sell_price / units / est_profit / est_fuel / margin`，让"跑商"从猜变成算。第一趟航电元件的 909 利润就是照它做的。
- **市场深度是真的**：连续成交会推动价格、清空库存，逼玩家换货换线，不是无限刷的假市场。
- **叙事与系统咬合**：首航委托把你推到黎明-02，正好路过矿带和炉心，第一次采掘、第一次跨星系、第一次交付在 57 天内自然串起来。
- **股权链路完整**：`equity_preview`（同意度/签字线/影响因素）→ `equity_inquiry`（签单、有效期、委托额度）→ `trade_equity`（交割），还带控制权下限（"至少保留 1518 股"）和"本轮委托额度已用完"这种拟人约束，比大多数同类游戏细。
- **观战窗口**：「意图 / 动作 / 结果 / 最近动作」四行让人能看懂 Agent 在干什么，配合 `set_intent` 很合适做解说。

## 14. 作弊：先走了内存，再发现游戏自带接口

**内存改写（可用）**
1. `ReadProcessMemory` 遍历 MEM_COMMIT + PAGE_READWRITE 区，搜 int64 `2400` → 37 个命中；
2. 买 1 单位电池让钱包变 `2394`，对同一批地址回读 → 只剩 **1 个**（`2684581276688`）；
3. `WriteProcessMemory` 写 `30000` → `observe` 立刻返回 `credits=30000`。说明钱包确实是唯一 int64，改写有效。

**但游戏本身就有 agent 作弊接口**（`agent_bridge.gd:773`）。观战面板右上角有「允许作弊」开关（`scripts/ui/agent_watch.gd:57`），打开后 `cheat` 动作可用：

| kind | 参数 | 行为 |
|---|---|---|
| `credits` | `amount` ±5000 | 钱包增减，单次封顶 5000 |
| `fuel` | — | 见下方 bug |
| `repair` | — | 名下所有舰船回满 HP 与装甲 |
| `trust` | `flag`、`amount` ±30 | 调整阵营信任 |
| `opinion` | `person`、`amount` ±30 | 调整个人好感 |
| `tick` | `days` 1–30 | 直接推进天数 |
| `reveal` | — | 全部星系标记为已见 |

这是文档里没写的接口，比内存改写安全得多。**`cheat fuel` 有 bug**：它执行 `vessel.fuel = Hulls.MODELS[kind].fuel`，而模型里的 `fuel` 是**每单位距离的耗油系数**（0.78），不是油箱容量。实测把 22.9 燃料直接写成 **0.78**，等于把人扔在深空断油。正确写法应是用 `MODELS[kind].fuel_capacity` 或至少 `max(vessel.fuel, capacity)`。

## 17. 更正：那两次 `game_exited` 不是崩溃

先前记成"崩溃"是误判。实际原因是**另一个 Agent 正在导出游戏**：`dist/StarrailLegacy.exe` 的 LastWriteTime 是 `04:28:00`，正好压在第二个实例退出的时刻（`04:27:50` 还出现了一个 0 字节日志）；导出过程替换 EXE / 关掉正在运行的进程，于是桥接读到 `game_exited`。

证据链：
- `StarrailLegacy.exe` 在 04:28 被重写（111,010,672 字节）；
- `%APPDATA%\Godot\app_userdata\星轨遗产\logs\` 在 04:16~04:17 一分钟内出现 4 个启动横幅日志，每份只有 `Godot Engine v4.6.3` + `All fixes check: 11~13/13`——这是导出/导入时的自检，不是玩家在反复启动；
- 两次"退出"都发生在这些日志轮次之间，且 `godot.log` 里没有任何异常栈。

**结论：与舰队规模、内存改写、长 `step` 都无关，撤回此前"有僚舰 + 交战后长步进会崩"的结论。** 教训是：跑 Agent 试玩时要确认没有别的构建任务在动同一个 `dist/*.exe`。

顺带保留一条有用信息：`godot.log` 里的启动自检会打印 `FAIL: peace treaty partially restores trust +8`、`FAIL: cheat allowed and capped at 5000` 这类条目，是回归排查的第一现场，但正常玩家看不到。

## 18. 打捞：走通了，但要先破"交战锁定"

`flight.gd:262 salvage()` 的判定：

```
if vessel.is_empty() or game.galaxy or vessel.dock != 0 or vessel.locked: return
for wreck in world.wrecks: if wreck.system == vessel.system and pos.distance_to(wreck.pos) < 95 and stock.max() > 0: ...
```

实测流程（第三局，种子 `深潜-1125-C`）：

1. 手动 chase 把海盗从 100 hp 打到 33 hp，敌舰脱离视野 → 后来回头再打，hp 18.8 时消失，**+¢830 赏金**，残骸留在最后的坐标 `(34.36,-855.82)`；
2. 但 `locked` 立刻卡住：`mine_or_salvage` 返回 `interaction_unavailable`，`dock` 报「交火中不能停靠」，`step` 只能 1 档。锁定判据是 `flight.gd:793 vessel.locked = target(vessel,520.0,true) != 0`——**只要 520 内还有敌对舰（哪怕它不在 `state.targets` 里），就一直锁着**；
3. 飞出 1,116 距离（speed 1，锁定时禁倍速，30 游戏日）→ `locked=false`；
4. 飞回残骸坐标 95 内 → `mine_or_salvage` 第一次收 **12 单位（合金 3 / 燃料 4 / 船体部件 1 / 废料 4）**，第二次再收 **4 单位废料**。残骸按 `min(撈臂上限, 库存)` 逐货种搬，捞空且没有 hull_id 才从 `world.wrecks` 删除。

**体验问题**：这套"先打、再跑 520 外等解锁、再飞回来捞"的流程，玩家几乎不可能自己想明白；而且残骸在解锁期间不受保护（没有提示"附近有残骸"），全靠记坐标。建议：①锁定判据改成"只算敌对且可见的船"；②残骸在 `observe` 里暴露 `wrecks[{pos, stock}]`，或在飞行 HUD 给个标记；③`targets` 为空时自动解锁。

## 24. 第五轮（day 7150 → 9265）：市场彻底饱和，跑商路线走死

这一轮把燃料、库存、报价三个机制都摸清了一遍，结论是**这个存档在 day 9000 之后已经没有可做的贸易**。

### 关键机制（读代码验证）

- `refuel` 不是单纯买油：`economy.gd:404` 先把手里的**燃料货物**（ware 2）倒进油箱（`from_cargo = min(cargo[2], 100 - fuel)`），再从港口库存补（`pump_fuel`，预算 = 钱包）。所以断油时可以先买 36 单位燃料货物再 `refuel`，实测把 12.5 补到 24.5。
- `market_available` 是**港口库存**，不是需求。拿它当"谁要买我的货"会一路撞墙：`trade_opportunities` 推荐的「航电元件 → 萨拉赫 557」到港 `market_quote` 直接 `units:0`；「净水 → 186」实收 10/单位（预估 34）；「船体部件 → 黎明-02站」到港直接 `units:0`。**判断能不能卖只有一条可靠路子：先 `market_quote` 报一次卖单。**
- 买断还多了一条前置：`charter.reason` 变成「人和船都须在登记港」——角色和船都要在晨曦自由港才能 `buyout_charter`。
